Chapter 1: Introduction

1.1 Background

Examination scheduling is one of the most critical and time-consuming administrative tasks faced by universities and educational institutions. As the number of courses and students grows, manually constructing a conflict-free examination timetable becomes increasingly difficult and error-prone. A conflict occurs when two subjects share one or more common enrolled students — in such cases, those subjects must not be assigned the same examination time slot.

The problem of examination timetabling belongs to a class of combinatorial optimization problems that can be elegantly modeled using Graph Theory, specifically the Graph Coloring Problem. This project leverages this mathematical model to build an automated, intelligent system that generates conflict-free timetables with minimal examination slots.

1.2 Problem Statement

Problem: Given a set of subjects and their student enrollment lists, automatically generate an examination timetable such that:
  • No two subjects that share common enrolled students are scheduled in the same time slot.
  • The total number of examination slots (days/sessions) is minimized.
  • The generated schedule is deterministic, verifiable, and reproducible.

This is equivalent to finding the chromatic number χ(G) of the conflict graph, where each subject is a vertex and edges connect subjects with common students. The chromatic number represents the minimum number of examination slots required.

1.3 Objectives

  1. To model the examination scheduling problem as a Graph Coloring problem.
  2. To implement Graph Coloring using a Backtracking algorithm with iterative deepening.
  3. To apply the Welsh-Powell heuristic for optimal vertex ordering.
  4. To build a full-stack web application with a modern, professional user interface.
  5. To provide real-time conflict detection, graph visualization, and timetable generation.
  6. To verify that the generated timetable contains zero scheduling conflicts.

1.4 Scope of the Project

The system is designed for university-level examination scheduling. It supports:

  • Up to 50+ subjects with arbitrary student enrollment combinations.
  • Automated detection of all conflict pairs from enrollment data.
  • Visual representation of the conflict graph with slot-based coloring.
  • REST API backend for data management and algorithm execution.
  • Responsive web interface accessible on desktop and tablet devices.

Chapter 2: Literature Review

2.1 Graph Coloring Problem

The Graph Coloring Problem (GCP) is a classical problem in combinatorial mathematics and theoretical computer science. Given an undirected graph G = (V, E), the goal is to assign a color to each vertex such that no two adjacent vertices share the same color, using the minimum number of colors possible. This minimum number is called the chromatic number χ(G).

The concept was first introduced by Francis Guthrie in 1852 through the famous Four Color Problem for maps. Its application to scheduling problems was formalized in the 1960s when researchers recognized that resource allocation and scheduling could be modeled as graph coloring instances.

Graph k-coloring for k ≥ 3 is known to be NP-Complete (Karp, 1972), meaning no known polynomial-time algorithm can solve all instances optimally. However, for practical instances with small vertex counts (such as university subjects), exact algorithms like backtracking with heuristics run efficiently in milliseconds.

2.2 Backtracking Technique

Backtracking is a systematic algorithmic technique for solving constraint satisfaction problems. It incrementally builds a solution and abandons ("backtracks") any partial solution as soon as it determines that the solution cannot be completed successfully. It was formalized by Golomb and Baumert (1965).

For graph coloring, backtracking explores assignments of colors to vertices one at a time. At each step, it checks whether the current assignment violates any constraint (i.e., whether any adjacent vertex has been assigned the same color). If a conflict is detected, it reverts the last assignment and tries the next color.

Chapter 5: Algorithm Design & Implementation

5.1 Graph Coloring — Theory

Let G = (V, E) be an undirected graph where:

  • V = {v₁, v₂, ..., vₙ} represents the set of subjects.
  • E = {(vᵢ, vⱼ) | subjects i and j share at least one common student}.
  • A k-coloring of G assigns a color from {1, 2, ..., k} to each vertex such that for every edge (u, v), color(u) ≠ color(v).
  • The chromatic number χ(G) is the minimum k for which a valid coloring exists.

Mapping to Exam Scheduling

Vertex (Node)Subject / Course
EdgeTwo subjects share ≥1 common student
ColorExamination time slot
Valid ColoringNo two conflicting subjects in the same slot
Chromatic Number χ(G)Minimum number of exam slots needed

5.2 Backtracking — Theory

Backtracking is a depth-first search over the space of partial assignments. At each step it assigns a slot to the next unscheduled subject. Before assigning, it calls the isSafe() function to verify that no neighboring subject (in the conflict graph) has already been assigned the same slot. If no valid slot exists for the current subject, the algorithm backtracks to the previous subject and tries the next available slot.

5.3 Welsh-Powell Ordering Heuristic

Before running backtracking, subjects are sorted in descending order of degree (number of conflicts). Subjects with more conflicts are colored first. This heuristic, known as the Welsh-Powell algorithm (1967), dramatically reduces the depth of backtracking in practice because highly-constrained subjects are assigned early when more slots are available.

5.4 Pseudocode

ALGORITHM: GraphColoringBacktracking(subjects)

INPUT : List of subjects with student enrollment
OUTPUT: Assignment { subjectId → slotNumber }, minimum slots used

STEP 1 — Build Conflict Graph:
  FOR each pair (sᵢ, sⱼ) of subjects:
    IF students(sᵢ) ∩ students(sⱼ) ≠ ∅:
      Add edge (sᵢ, sⱼ) to adjacency list

STEP 2 — Sort by Degree (Welsh-Powell):
  sortedSubjects ← sort(subjects, by degree DESC)

STEP 3 — Iterative Deepening:
  FOR k = 1 TO |subjects|:
    assignment ← {}
    IF Backtrack(0, sortedSubjects, k, assignment):
      RETURN assignment    ← minimum k found ✓

FUNCTION Backtrack(idx, subjects, maxSlots, assignment):
  IF idx == |subjects|: RETURN true    ← all assigned

  subject ← subjects[idx]
  FOR slot = 1 TO maxSlots:
    IF isSafe(subject, slot, assignment):
      assignment[subject] ← slot
      IF Backtrack(idx+1, subjects, maxSlots, assignment):
        RETURN true
      DELETE assignment[subject]        ← BACKTRACK ↩

  RETURN false

FUNCTION isSafe(subject, slot, assignment):
  FOR EACH neighbor IN adjacency[subject]:
    IF assignment[neighbor] == slot:
      RETURN false    ← conflict detected
  RETURN true

Chapter 8: Conclusion & Future Work

8.1 Conclusion

This project successfully demonstrates the application of Graph Coloring with Backtracking to the real-world problem of university examination scheduling. The key achievements of this project are:

  • A fully functional full-stack web application with six feature-rich pages.
  • Exact implementation of backtracking with iterative deepening that guarantees the chromatic number — the theoretical minimum number of exam slots.
  • Welsh-Powell heuristic ordering for practical performance improvement.
  • Automatic conflict detection from student enrollment data.
  • Interactive SVG conflict graph visualization with slot-based coloring.
  • REST API with 8 endpoints for complete CRUD and timetable operations.
  • Verified zero violations across all 34 conflict pairs in the sample dataset.
  • Execution time of 0.457ms for 10 subjects — extremely efficient.

The system proves that classical algorithms from graph theory, when implemented correctly and paired with modern web technologies, can solve practical administrative problems efficiently and reliably.
